# AutoPet v0.1 Manual E2E Smoke Checklist

## Purpose

This checklist is a manual v0.1 end-to-end smoke run for:

```text
Maker transparent PNG export -> generated pet package -> Runtime Load Pet... -> displayed/animated desktop pet
```

Use it to gather release-decision readiness evidence. This checklist is not a
release, and passing it does not publish or declare a v0.1 release.

## Scope

This smoke covers:

- Maker transparent PNG export.
- Generated package file shape.
- Runtime `Load Pet...`.
- Basic Runtime behavior after loading the generated pet.

## Non-Goals

This smoke does not cover:

- Installer creation.
- GitHub Release binaries.
- Release publishing.
- CI implementation.
- Zip export.
- Persistent settings.
- Runtime launch-from-Maker.
- `rembg`.
- System tray.
- Multi-pet.
- Plugin system.
- New animation features.

## Preconditions

- Use Windows 10/11.
- Start from clean `main`, then create a small task branch for the smoke.
- Use PowerShell from the repository root.
- Install JavaScript dependencies with:

```powershell
corepack pnpm install
```

- Confirm the local Python virtual environment exists at `.venv`.
- Install Python image-pipeline requirements from
  `packages\image-pipeline\requirements.txt`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r packages\image-pipeline\requirements.txt
```

- Keep smoke input and output files outside the repository, for example under:

```powershell
$env:TEMP\autopet-v0.1-e2e-smoke
```

## Optional Temporary Transparent PNG

If you need a disposable transparent PNG input, create one outside the
repository:

```powershell
$SmokeRoot = Join-Path $env:TEMP "autopet-v0.1-e2e-smoke"
$InputPng = Join-Path $SmokeRoot "input-transparent.png"
New-Item -ItemType Directory -Force -Path $SmokeRoot | Out-Null

@"
from pathlib import Path
from PIL import Image, ImageDraw

path = Path(r"$InputPng")
image = Image.new("RGBA", (160, 160), (0, 0, 0, 0))
draw = ImageDraw.Draw(image)
draw.ellipse((30, 18, 130, 118), fill=(255, 120, 60, 255))
draw.rectangle((68, 92, 92, 144), fill=(60, 150, 240, 230))
image.save(path, "PNG")
print(path)
"@ | .\.venv\Scripts\python.exe -
```

Do not add this image to the repository.

## Baseline Verification Commands

Run these from the repository root before or during the smoke. If a command is
skipped, record the command and the reason in the smoke result.

```powershell
git diff --check
corepack pnpm typecheck
corepack pnpm build
corepack pnpm --filter @autopet/image-pipeline typecheck
corepack pnpm --filter @autopet/image-pipeline test
.\.venv\Scripts\python.exe -m compileall packages\image-pipeline\autopet_image_pipeline
.\.venv\Scripts\python.exe -m unittest discover -s packages\image-pipeline
```

## Manual E2E Checklist

- [ ] Confirm the working tree is clean before the smoke:

```powershell
git status --short --untracked-files=all
```

- [ ] Create or choose a transparent PNG input outside the repository.
- [ ] Create an empty output folder outside the repository.
- [ ] Launch Maker:

```powershell
corepack pnpm dev:maker
```

- [ ] In Maker, choose the transparent PNG.
- [ ] In Maker, choose the empty output folder outside the repository.
- [ ] Enter a pet name.
- [ ] Export the package.
- [ ] Verify the generated output folder contains:
  - [ ] `pet.json`
  - [ ] `spritesheet.png`
  - [ ] `preview.gif`
- [ ] Verify `pet.json` references `spritesheet.png` in the `sprite` field.
- [ ] Launch Runtime from a separate PowerShell window:

```powershell
corepack pnpm dev:runtime
```

- [ ] Open the Runtime right-click menu.
- [ ] Use `Load Pet...`.
- [ ] Select the generated package folder.
- [ ] Verify the generated pet displays.
- [ ] Verify the animation advances visibly.
- [ ] Drag the pet window.
- [ ] Use `Reset Position`.
- [ ] Toggle `Always on Top` off and on.
- [ ] Exit Runtime cleanly.
- [ ] Stop the Maker dev process cleanly.
- [ ] Confirm no generated smoke files were created inside the repository:

```powershell
git status --short --untracked-files=all
```

## Pass Criteria

- All baseline commands pass, or any skipped command is explicitly recorded with
  the reason.
- Maker export succeeds.
- Runtime loads the generated package without validation or load errors.
- The pet displays and animates.
- Runtime basic controls work.
- No generated smoke files are committed.

## Failure Handling

- Record the exact failure, including command output, UI message, input path,
  output path, and the step that failed.
- Do not fix unrelated bugs in this docs PR.
- If a bug is found, create a separate small bugfix PR after this checklist PR.
